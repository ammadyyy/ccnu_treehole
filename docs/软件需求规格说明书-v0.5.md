## 1. 项目概述

### 1.1 产品目标

回声洞是一个面向本校学生的匿名公共树洞社区。用户注册账号后领取一个或多个随机面具，以面具身份在全站树洞墙发布帖子、上传图片、回应其他帖子，并接收自己发布的帖子收到新回应的通知。

产品重点是轻松、好玩、低门槛的校园匿名表达。

### 1.2 产品范围

本期实现：

- 邮箱 + 密码注册和登录；
- 登录后领取、销毁和切换随机面具；
- 使用当前面具发布带标签的文字帖子；
- 发布时可附带图片；
- 树洞墙浏览、标签筛选、最新排序和 24 小时热门排序；
- 帖子详情和单层匿名回应；
- 中文关键词搜索；
- 帖子作者收到新回应通知；
- 删除自己的帖子和回应；
- PVE LXC 容器部署，校园网访问；
- 为后续接入域名、HTTPS 和迁移保留配置与数据分离能力。

暂不实现：

- 真实邮箱验证码；
- 忘记密码实际流程；入口保留，但显示“开发中......敬请期待”；
- 私信、关注、点赞、排行榜、评论盖楼；
- 移动端 App、WebSocket、SSE；
- 敏感词待审与账号封禁（举报、审核与管理员后台已在本版确认，见 FR-13、FR-14）；
- 公开互联网部署和 HTTPS；
- 多租户和多语言。

### 1.3 产品边界

本产品是公共树洞社区：

- 所有已发布帖子进入统一树洞墙；
- 用户通过固定面具在不同帖子中保持可识别的面具身份；
- 账号本身及账号拥有的其他面具不向普通用户展示。

## 2. 用户与身份模型

### 2.1 用户类别

| 用户类别 | 权限概述 |
|---|---|
| 游客 | 浏览树洞墙、查看公开帖子详情、搜索、按标签筛选、注册、登录 |
| 普通用户 | 领取和销毁面具、发帖、回应、删除自己的内容、查看和处理自己的通知 |
| 普通管理员 | 处理举报、查看内容与面具映射、查看自己的审计日志；不能管理管理员账号 |
| 超级管理员 | 在普通管理员权限之上，可创建、停用、重置普通管理员，可查看全部审计日志 |

### 2.2 账号

- 使用邮箱和密码注册。
- 演示版不发送、不校验真实邮箱验证码。
- 邮箱用于登录和标识站内账号，不代表已经验证真实身份。
- 注册成功后不自动领取面具。
- 没有可用面具时不能发布帖子或回应。
- 演示版不实现忘记密码；登录页保留入口，点击后显示“开发中......敬请期待”。

### 2.3 面具

面具是账号派生出的公开发言身份，格式示例：

```text
匿名者·k7f2
```

规则：

1. 每个账号最多同时持有 5 个可用面具。
2. 已销毁面具不占用 5 个名额。
3. 面具由服务端随机生成，全局唯一。
4. 面具名称永久不复用。
5. 销毁面具后，历史帖子和回应仍显示原面具名称，并标记“已销毁面具”。
6. 面具名称不可点击，不提供面具公开主页。
7. 普通用户不能通过公开页面判断两个面具是否属于同一个账号。
8. 同一个面具在不同帖子中显示相同名称，因此不同帖子可以关联到同一个面具。

### 2.4 当前登录期间的面具选择

- 每次登录后，用户必须自行选择本次访问使用的面具。
- 选择结果在当前登录期间持续有效，刷新页面、切换页面不会改变。
- 发帖和回应默认都使用当前选择的面具，不在每个表单中重复选择。
- 用户可以在“我的面具”页主动切换当前面具。
- 切换面具不会修改历史帖子和回应的作者面具。
- 销毁当前使用的面具后，账号保持登录，但当前面具被清空；用户必须重新选择或领取面具后才能发帖、回应。
- 销毁面具后，可以使用新的面具继续回应此前参与过的帖子；历史回应保持原面具。
- 同一帖内允许同一账号切换不同面具进行回应。
- 只有使用发布该帖的原面具回应时，回应显示“楼主”标记；使用同账号的其他面具回应不显示“楼主”。

## 3. 技术与部署约束

### 3.1 技术栈

| 层次 | 选择 |
|---|---|
| 后端 | Python 3.13 + Flask |
| API | Flask JSON API，统一使用 `/api/*` |
| 前端 | Vite + React + TypeScript |
| 路由 | React Router |
| 样式 | Tailwind CSS，所有资源本地打包 |
| 数据库 | SQLite 单文件数据库 |
| 图片 | 本地文件系统，数据库保存相对路径 |
| 会话 | httpOnly Cookie，会话由服务端管理 |
| 密码 | Werkzeug PBKDF2 哈希 |
| 部署 | PVE LXC 容器 + Debian/Ubuntu + systemd |

### 3.2 当前运行方式

```text
学生浏览器
    │ 校园网 IP + 端口
    ▼
PVE
    │
    ▼
LXC 容器
    ├── Flask API + 静态前端
    ├── SQLite 数据库
    └── uploads 图片目录
```

当前演示不配置域名、HTTPS 或反向代理。应用监听地址和端口必须通过配置指定，不写死在业务代码中。

### 3.3 迁移要求

- 数据库文件和图片目录与程序代码分离。
- 数据目录通过环境变量配置。
- 图片只保存相对路径，不保存服务器绝对路径。
- 前端 API 使用同源相对路径 `/api/...`。
- 分享地址、站点地址统一通过 `APP_URL` 配置。
- 不使用 SQLite 专用以外的复杂数据库语法，后续可迁移到 PostgreSQL。
- 将来购买域名后，只需修改 DNS、`APP_URL` 和反向代理配置。
- 将来迁移服务器时，复制代码、数据库文件和图片目录即可恢复主要数据。

建议配置：

```dotenv
APP_ENV=demo
APP_URL=http://校园网服务器IP:端口
HOST=0.0.0.0
PORT=8000
DATA_DIR=/srv/echohole/data
DATABASE_PATH=/srv/echohole/data/echohole.db
UPLOAD_DIR=/srv/echohole/data/uploads
COOKIE_SECURE=false
```

## 4. 功能需求

### FR-01 注册

用户输入邮箱和密码注册。

规则：

- 校验邮箱格式和唯一性。
- 密码至少 8 位，并同时包含字母和数字。
- 演示版不发送验证码，注册成功后直接进入登录态或登录页面。
- 同一邮箱不能重复注册。
- 注册成功后不自动领取面具。
- 注册页应引导用户前往“我的面具”领取面具。
- 当前面具记录在会话表 `sessions.current_mask_id`，注册与登录时为 NULL，用户选择或切换时写入，销毁当前面具时清空。

验收：

- 新邮箱可注册。
- 弱密码被拒绝。
- 重复邮箱被拒绝。
- 注册后没有面具时不能发帖和回应。

### FR-02 登录、登出与会话

用户使用邮箱和密码登录，服务端通过 httpOnly Cookie 维护会话。

规则：

- 登录成功后进入当前面具选择流程。
- 登出后服务端销毁当前会话。
- 会话不使用 JWT。
- 登录页提供“忘记密码”入口；点击后显示“开发中......敬请期待”，不进入实际找回流程。
- 登录成功后，若用户没有可用面具，应提示先领取面具。

### FR-03 面具领取

用户在“我的面具”页领取随机面具。

规则：

- 每个账号最多同时拥有 5 个可用面具。
- 面具格式为“匿名者·”加 4 位随机小写字符。
- 面具字符集应剔除容易混淆的字符。
- 服务端保证面具名称全局唯一。
- 达到上限后不能继续领取。

### FR-04 面具销毁

用户可以在“我的面具”页销毁自己的面具。

规则：

- 只需弹窗确认，不要求输入发帖数。
- 弹窗必须说明：销毁后不能再使用，历史内容仍会保留。
- 销毁后不能用该面具发新帖或回应。
- 历史帖子和回应继续保留原面具名称，并显示“已销毁面具”。
- 销毁名称永久不再分配给其他用户。
- “我的面具”页保留“已销毁面具”分组。
- 用户可以在该分组查看、删除该面具历史发布的帖子。

### FR-05 当前面具选择

- 每次登录后必须选择一个可用面具。
- 选择期间持续使用同一面具。
- 可在“我的面具”页切换面具。
- 切换后后续新帖和新回应使用新面具。
- 历史内容的面具不变。
- 当前面具被销毁后，要求重新选择或领取。

### FR-06 发布帖子

登录且已选择可用面具的用户可以发布帖子。

字段：

- 标题：必填，1–50 个 Unicode 字符，单行且不允许换行。
- 正文：必填，1–2000 个 Unicode 字符（去除首尾空白后不能为空）。
- 标签：固定标签中选择 1–2 个。
- 图片：可选，最多 3 张，每张可带一句说明。

固定标签：

```text
学业、情感、吐槽、求助、深夜、失物、其他
```

图片说明：

- 可选，单行纯文本，最多 100 字符。
- 禁止出现 URL 或裸域名。
- 只作为图片的替代文本（`alt`）与大图预览说明，不参与排序、搜索与推送。

规则：

- 发布时使用当前登录期间选择的面具。
- 不提供“无面具发布”或显示账号昵称的选项。
- 超出长度上限时给出中文字数提示，不静默截断。
- 发布后不能编辑正文、标签或图片。
- 只能删除后重新发布。
- 发帖频率按账号限制为每 30 秒最多一次。
- 切换面具不会重置发帖计时。
- 成功发布后进入帖子详情或树洞墙，并显示新帖。

验收：

- 正文为空或只有空白时被拒绝。
- 标题 50 字符可以发布，51 字符被拒绝并提示上限。
- 正文 2000 字符可以发布，2001 字符被拒绝并提示上限。
- 未选标签或选 3 个标签时被拒绝。
- 700ms 内连续发第二帖被拒绝。

### FR-07 图片上传

用户在发帖页面选择图片后，先在浏览器本地预览；点击“发布”时与正文一起上传。

规则：

- 每帖最多 3 张。
- 单张上传文件原始大小上限为 5 MB；动画处理后的大图 WebP 不得超过 10 MB。
- 支持 JPEG、PNG、WebP、GIF；静态图统一转换为 WebP，GIF 和动画 WebP 转换为动画 WebP。
- 服务端校验文件头魔数，不仅信任扩展名或 MIME 类型。
- 按 EXIF 方向信息校正图片朝向。
- 剥离 EXIF、GPS 等全部元数据后再落盘。
- 静态图统一转为 WebP，quality 85。
- 为每张图生成缩略图；静态图和动画图缩略图均不超过 1 MB，动画缩略图只保留第一帧。
- 使用随机 UUID 生成文件名。
- 图片保存到独立的 `uploads` 目录。
- 数据库保存原图与缩略图的相对路径、大小、宽高、是否动画和图片说明。
- 图片不做去重，相同图片每次上传都独立保存。
- 图片发布时才落盘，取消发帖不产生服务器图片文件。
- 删除帖子时立即删除该帖的原图和缩略图。
- 图片删除后，数据库关联记录同步删除，不能留下失效公开 URL。

验收：

- 把 `.exe` 改名为 `.jpg` 上传被拒绝。
- 6 MB 静态图被拒绝，9 MB 动画图可以上传。
- 上传后的原图不含 EXIF，朝向正确，格式为 WebP。
- 取消发帖后服务器 `uploads` 目录没有新增文件。

### FR-08 树洞墙

树洞墙是全站统一的公开信息流，游客无需登录即可浏览。

帖子卡片展示：

- 面具名称；
- “已销毁面具”或“已注销面具”标记（如适用）；
- 标签；
- 正文摘要；
- 图片缩略图；
- 回应数量；
- 相对发布时间。

排序与筛选：

- “最新”：按帖子发布时间从新到旧，使用 `created_at + id` 游标，每次加载 20 条。
- “24 小时最热”：只展示最近 24 小时内回应数最高的前 20 条；刷新时重新计算排名，不提供持续翻页。
- 热门结果支持标签筛选，标签条件参与同一份排名计算。
- 热门缓存：全站与 7 个标签共 8 份进程内缓存，有效期 5 分钟；缓存过期时先返回旧结果，再在后台刷新，不阻塞请求。
- 标签筛选支持单标签。
- 帖子详情和公开列表不显示账号邮箱或其他面具关系。

验收：

- 无缓存冷启动时热门接口仍能返回结果。
- 新增回应后 5 分钟内热门排名可能不变，5 分钟后刷新。
- 按标签筛选热门时只出现该标签的帖子。

### FR-09 帖子详情与匿名回应

帖子详情展示完整正文、图片和回应列表。

布局：

- 图片在正文上方，多图使用横向相册。
- 相册中单张图片最大高度为视口高度的 60%，不裁剪图片。
- 详情页自然滚动，回应列表不设固定高度。
- 桌面端使用左右按钮与键盘方向键切换，移动端在相册区域内滑动切换。
- 相册不自动轮播，预加载相邻图片。

规则：

- 回应采用单层结构，回应不能再被回应。
- 回应正文 1–500 个 Unicode 字符，并给出中文字数提示。
- 回应使用当前登录期间选择的面具。
- 回应发布频率按账号限制为每 30 秒最多一次，与发帖计时互不影响。
- 切换面具不会重置回应计时。
- 同一帖内允许同一账号切换不同面具回应。
- 使用发帖面具回应时显示“楼主”；其他面具不显示。
- 回应发布后不能编辑，只能删除后重新发布。
- 作者删除帖子后，该帖正文、回应和图片均被彻底删除。

回应列表：

- 初次加载 20 条，按发布时间从早到晚排列。
- 滚动接近底部时自动加载更多。
- 用户发布回应成功后，自动定位到刚发布的回应。
- 详情页每 30 秒检查一次新回应。
- 发现新回应时显示“有 N 条新回应”，不打断当前阅读位置。
- 用户点击提示后加载新回应。

验收：

- 含 5 张图的帖子在桌面端可用键盘切换相册，单图高度不超过 60vh。
- 回应 500 字符可以发布，501 字符被拒绝。
- 回应 200 条的帖子详情页可以整页自然滚动。

### FR-10 删除帖子与回应

#### 删除帖子

- 只有帖子作者可以删除自己的帖子。
- 已销毁面具的历史帖子仍可由账号在“我的面具”页删除。
- 删除权限按“该面具是否属于当前账号”校验，不要求用户切回原面具。
- 删除前显示确认弹窗，说明删除后不可恢复。
- 删除顺序：先提交数据库事务删除帖子、回应与图片记录，事务提交后再删除磁盘上的原图与缩略图。
- 文件删除失败只记录日志，不回滚已提交的删除，不把内容重新暴露。
- 删除后旧帖子 URL 返回内容不存在状态。
- 已产生的通知保留占位信息“内容已删除”，不得保留正文摘要。
- 管理员删除内容同样不可恢复，并须记录审计日志（见 FR-14）。

#### 删除回应

- 只有回应作者可以删除自己的回应。
- 删除前显示确认弹窗。
- 删除后回应正文彻底删除。
- 帖子回应数量同步更新。
- 相关通知显示“内容已删除”。
- 不提供编辑接口。

验收：

- 用已销毁面具发布的帖子，账号仍能删除。
- 删除后数据库无残留记录，磁盘无残留文件。
- 手工制造文件删除失败时，帖子仍不再可见，日志中有失败记录。

### FR-11 搜索

游客和登录用户都可以搜索公开帖子和公开回应。

规则：

- 允许单字及以上关键词。
- 一个或两个字符使用参数化 `LIKE` 子串查询。
- 三个及以上字符使用 SQLite FTS5 trigram 检索。
- 正文命中与回应命中合并为一条帖子结果，每个帖子只出现一次。
- 搜索结果按帖子发布时间从新到旧。
- 支持同时选择标签筛选；结果必须同时满足关键词和标签条件。
- 被删除或非公开内容不得出现在搜索结果。
- 搜索无结果时显示明确空状态文案。
- 用户输入必须参数化，不能拼接 SQL。

验收：

- 搜索「图」能命中含「图书馆」的帖子。
- 搜索「图书馆」走 trigram 检索，结果与单字搜索一致且不重复。
- 搜索关键词中含引号或分号时不报错、不改变查询语义。

### FR-12 通知

通知只针对用户自己发布的帖子。

规则：

- 别人回应自己的帖子时，生成一条独立通知。
- 自己回应自己的帖子不生成通知。
- 每条回应对应一条通知，不合并通知。
- 通知归属于账号，而不是某个单独面具。
- 通知内容应显示触发回应的面具名称和所属帖子信息。
- 面具销毁后，历史通知仍可查看。
- 面具销毁后，该面具历史发布的帖子不再产生新通知。
- 通知永久保留，演示版不做过期清理。
- 通知页提供未读数量和红点。
- 点击某条通知时，该条标记为已读。
- 提供“全部标为已读”按钮。
- 仅打开通知页不会自动清空全部未读状态。
- 通知数量每 30 秒自动检查一次，页面重新获得焦点时立即检查。
- 对已彻底删除的帖子，通知显示“内容已删除”，不显示正文摘要。

### FR-13 举报

登录用户可以对违规帖子或回应发起举报。

规则：

- 只有登录用户可以举报，游客没有举报入口。
- 举报需要选择原因（如广告、辱骂、色情、违法、泄露隐私、其他），可附说明。
- 同一用户可以对同一内容重复举报，但每分钟最多 3 次。
- 被举报内容不会自动隐藏，仍公开展示，直到管理员处理。
- 管理员可以选择“保留”或“删除”并结案。
- 删除后不可恢复，必须选择固定理由并填写不少于 10 字的说明，且需二次确认。
- 举报队列按每个目标的待处理举报数量降序排列；数量相同时按该目标最新一条待处理举报的时间升序排列。
- 举报队列支持按原因和状态筛选。
- 结案不通知被举报的作者。

验收：

- 游客访问举报接口返回未授权。
- 同一账号一分钟内第 4 次举报被拒绝。
- 被举报帖子在管理员处理前仍可从树洞墙打开。
- 管理员删除后该帖返回内容不存在，且审计日志新增一条。

### FR-14 管理员与审计

管理员分为超级管理员与普通管理员两级。

角色规则：

- 系统只有一名超级管理员，可由初始化脚本创建。
- 超级管理员可以创建、停用、重置普通管理员。
- 普通管理员不能创建、停用或重置管理员账号。
- 不提供网页端的提权入口，管理员身份只能通过初始化脚本或超级管理员授予。

管理员账号规则：

- 创建普通管理员必须使用尚未注册的邮箱。
- 初始密码为临时密码，永久有效，不强制首次登录修改。
- 超级管理员重置普通管理员密码时需要填写理由并二次确认。
- 停用管理员邮箱后，该邮箱继续绑定原账号，只允许恢复原账号，不释放给新的管理员账号。

后台功能：

- 后台首页展示待处理举报数、今日新增帖子与回应等统计，每 30 秒刷新，按服务器自然日统计“今日新增”。
- 举报队列与举报详情：见 FR-13。
- 管理员可以在举报详情中查看该内容对应的面具，必要时查看面具对应的站内账号。
- 查看普通面具的映射关系不写审计日志；查看已注销面具的映射关系必须写审计日志。

审计日志：

- 记录管理员敏感操作：删除内容、处理举报、创建/停用管理员、重置密码、查看已注销面具映射。
- 每条日志包含操作人、动作、目标、理由说明与时间。
- 审计日志只读，不提供修改和导出。
- 普通管理员只能查看自己产生的审计日志，超级管理员可以查看全部。

验收：

- 普通管理员访问管理员管理接口返回禁止。
- 超级管理员删除内容时不填说明或理由无法提交。
- 普通管理员在审计日志页看不到超级管理员的记录。
- 查看已注销面具映射后，审计日志新增一条；查看普通面具映射不新增。

### FR-15 账号设置与注销

登录用户可以在“账号设置”中修改密码和注销账号。

修改密码规则：

- 需要先输入当前密码。
- 新密码规则与注册一致：至少 8 位并同时包含字母和数字。
- 修改成功后保留当前会话，注销该账号在其他设备上的会话。
- 失败时给出中文原因，不透露账号是否存在。

注销账号规则：

- 需要输入密码并二次确认，确认文案说明“注销后不可登录，历史内容保留”。
- 注销后该账号的历史帖子、回应与图片保留，公开身份统一显示为“已注销面具”。
- 注销后该账号的通知删除。
- 注销后原邮箱可以重新注册，新账号与旧账号的数据完全隔离。
- 注销后不能再登录、发帖或回应。

退出登录：

- 退出登录需要确认。

验收：

- 旧密码错误时修改被拒绝。
- 修改密码后原会话仍可用，其他设备的会话立即失效。
- 注销后原邮箱可以注册新账号，且看不到旧账号的通知。
- 注销账号的历史帖子在树洞墙显示“已注销面具”。

## 5. 典型用例

本章把第 4 章的功能需求串成可演示、可验收的场景。每个用例列出关联需求编号，验收时按「主流程 + 异常流程」逐条走一遍即可。

### UC-01 注册账号并领取面具

- 参与者：游客
- 前置条件：尚未注册。
- 关联需求：FR-01、FR-03、FR-05

**主流程**

1. 打开注册页，输入邮箱与密码。
2. 服务端校验邮箱格式、邮箱唯一性与密码强度（至少 8 位且同时含字母和数字）。
3. 注册成功，直接建立登录态。
4. 系统提示「还没有面具」，引导用户前往「我的面具」。
5. 用户点击领取，得到形如 `匿名者·k7f2` 的面具。
6. 用户将其设为当前面具。

**异常流程**

- 邮箱已被注册：提示「该邮箱不可用」，不创建账号。
- 密码不合规：提示「至少 8 位，需同时包含字母和数字」。
- 已持有 5 个可用面具时领取：提示已达上限，拒绝第 6 次领取。

**后置条件**

- 账号已创建并处于登录态；用户完成领取和选择后，持有 1 个可用面具，会话中记录该面具为当前面具；若尚未领取，则不能发帖或回应。

### UC-02 登录并选择当前面具

- 参与者：普通用户
- 前置条件：已注册，且至少持有 1 个可用面具。
- 关联需求：FR-02、FR-05

**主流程**

1. 打开登录页，输入邮箱与密码。
2. 服务端校验通过，签发 httpOnly 会话 Cookie。
3. 会话中没有当前面具时，停在面具选择界面。
4. 用户选择一个可用面具。
5. 服务端把当前面具写入会话，进入树洞墙。

**异常流程**

- 密码错误：提示「邮箱或密码错误」，不建立会话。
- 名下没有可用面具：提示先领取面具，不发帖入口。
- 账号状态不允许登录（若后续启用封禁）：拒绝登录并提示联系管理员。

**后置条件**

- 会话有效；当前面具保存在服务端，刷新与跨页不变。

### UC-03 切换当前面具

- 参与者：普通用户
- 前置条件：已登录，且持有至少 2 个可用面具。
- 关联需求：FR-05

**主流程**

1. 进入「我的面具」页，列表显示全部可用面具。
2. 用户选择另一个面具点击「设为当前」。
3. 服务端更新会话中的当前面具。
4. 之后的新帖与新回应使用新面具。

**异常流程**

- 提交的面具 ID 不属于本账号或已销毁：拒绝，并保持原当前面具。
- 未登录调用切换接口：返回未授权状态。

**后置条件**

- 历史帖子与回应的作者面具不变。

### UC-04 发布带图帖子

- 参与者：普通用户
- 前置条件：已登录，且已选择可用面具。
- 关联需求：FR-06、FR-07

**主流程**

1. 打开写树洞页。
2. 输入正文，选择 1–2 个固定标签。
3. 选择最多 3 张图片，浏览器本地预览。
4. 点击发布，服务端校验正文非空、标签数量、图片格式与大小。
5. 服务端保存图片文件与记录，写入帖子。
6. 跳转到帖子详情，卡片显示面具名、标签、摘要与相对时间。

**异常流程**

- 正文只有空白：拒绝并提示正文必填。
- 未选标签或选了 3 个及以上：拒绝并提示必须选 1–2 个。
- 图片超过 3 张、单张超过 5 MB、或魔数校验不通过：拒绝上传。
- 距上次发帖不足 30 秒：拒绝并提示操作过于频繁。
- 取消发布：不产生任何服务器图片文件。

**后置条件**

- 帖子进入树洞墙；此时不产生通知。

### UC-05 浏览树洞墙与标签筛选

- 参与者：游客或普通用户
- 前置条件：无
- 关联需求：FR-08

**主流程**

1. 打开树洞墙，默认「最新」排序。
2. 向下滚动，接近底部时加载更多。
3. 点击某个标签，列表只显示该标签的帖子。
4. 切换到「24 小时最热」，显示最近 24 小时回应数最高的前 20 条。

**异常流程**

- 该标签下没有帖子：显示空状态文案。
- 「24 小时最热」不提供继续翻页，滚动到底即结束。

**后置条件**

- 无数据写入。

### UC-06 回应帖子

- 参与者：普通用户
- 前置条件：已登录且已选择当前面具；帖子公开可见。
- 关联需求：FR-09、FR-12

**主流程**

1. 打开帖子详情，完整正文、图片与回应列表可见。
2. 详情页自然滚动，图片在正文上方以横向相册展示，回应列表初次加载 20 条，按时间从早到晚排列。
3. 用户输入回应并提交。
4. 服务端校验长度与频率，写入回应，帖子回应数加 1。
5. 若回应者账号与帖子作者账号不同，为帖子作者生成一条通知。
6. 界面自动定位到刚发布的回应。

**异常流程**

- 未选择当前面具：引导先选择或领取面具。
- 距上次回应不足 30 秒：拒绝并提示操作过于频繁。
- 帖子已被作者删除：返回内容不存在。
- 用非发帖原面具回应：成功，但不显示「楼主」。
- 停留期间帖子有新回应：显示「有 N 条新回应」，不打断阅读位置，点击后加载。

**后置条件**

- 回应落库；作者账号收到一条通知。

### UC-07 查看通知并标记已读

- 参与者：普通用户
- 前置条件：已登录，账号已有通知。
- 关联需求：FR-12

**主流程**

1. 导航栏显示通知红点与未读数量。
2. 打开通知页，列表显示触发回应的面具名与帖子摘要。
3. 点击某条通知，该条标记为已读并跳转到对应帖子。
4. 返回后未读数量相应减少。
5. 用户可点击「全部标为已读」一次性清零。

**异常流程**

- 对应帖子已被彻底删除：条目显示「内容已删除」占位，不显示正文摘要，不可跳转。
- 通知页每 30 秒自动检查；页面重新获得焦点时立即检查。

**后置条件**

- 仅打开列表不会清空未读状态，必须逐条点击或显式全部已读。

### UC-08 关键词与标签搜索

- 参与者：游客或普通用户
- 前置条件：无
- 关联需求：FR-11

**主流程**

1. 在搜索框输入至少 1 个字符。
2. 可选同时选择一个标签。
3. 服务端检索正文与回应正文。
4. 结果按帖子聚合，每个帖子只出现一次，按发布时间从新到旧。
5. 滚动加载更多结果。

**异常流程**

- 关键词为空：不发起请求。
- 无结果：显示空状态文案。
- 被删除或非公开内容：不出现在结果中。

**后置条件**

- 无数据写入。

### UC-09 删除自己的帖子

- 参与者：普通用户
- 前置条件：本人发布的帖子（含已销毁面具的历史帖）。
- 关联需求：FR-10

**主流程**

1. 在帖子详情或「我的面具」页找到目标帖子。
2. 点击删除，弹出确认框。
3. 确认后服务端在同一事务内删除回应、图片记录与帖子本身，并删除图片文件。
4. 旧帖子地址返回内容不存在。
5. 相关通知保留「内容已删除」占位。

**异常流程**

- 操作者不是作者：拒绝并返回权限不足。
- 帖子已删除：返回内容不存在。
- 弹窗中取消：不做任何变更。

**后置条件**

- 内容不可恢复，无残留公开地址。

### UC-10 销毁面具并保留历史

- 参与者：普通用户
- 前置条件：已登录，目标面具处于可用状态。
- 关联需求：FR-04、FR-05

**主流程**

1. 进入「我的面具」页。
2. 对目标面具点击销毁，弹窗说明「销毁后不能再使用，历史内容仍会保留」。
3. 确认后服务端把面具状态置为已销毁。
4. 若销毁的是当前面具，会话中的当前面具被清空。
5. 系统提示重新选择或领取面具后才能发帖、回应。

**异常流程**

- 销毁他人面具：拒绝。
- 面具已销毁：提示已不可用。
- 清空当前面具后直接发帖：引导先选择面具。

**后置条件**

- 历史帖子与回应仍显示原面具名并标注「已销毁面具」；该名称永久不再分配。

### UC-11 举报违规帖子

- 参与者：普通用户
- 前置条件：已登录，目标帖子或回应公开展示。
- 关联需求：FR-13

主流程：

1. 在帖子详情或回应上点击“举报”。
2. 选择举报原因，可填写说明。
3. 提交后提示“已收到举报，等待处理”。

异常流程：

- 未登录：不显示举报入口，直接调用接口返回未授权。
- 一分钟内第 4 次举报：提示“操作过快，请稍后再试”。
- 内容已被删除：提示内容不存在。

后置条件：

- 生成一条待处理举报记录，内容保持公开。

### UC-12 管理员处理举报

- 参与者：管理员
- 前置条件：管理员已登录，举报队列中存在待处理记录。
- 关联需求：FR-13、FR-14

主流程：

1. 打开后台举报队列，按待处理数量排序查看。
2. 选择一条举报进入详情，查看内容与面具映射。
3. 判断后选择“保留”或“删除”。
4. 删除时选择固定理由并填写不少于 10 字的说明，二次确认。
5. 结案后队列中该目标记录消失，审计日志新增一条。

异常流程：

- 普通管理员尝试创建或停用管理员：返回禁止。
- 理由缺失或说明不足 10 字：提交被拒绝。

后置条件：

- 保留的内容继续公开；删除的内容彻底删除且不可恢复。

### UC-13 修改密码与注销账号

- 参与者：普通用户
- 前置条件：已登录。
- 关联需求：FR-15

主流程：

1. 进入“个人中心 → 账号设置”。
2. 修改密码：输入当前密码与新密码，提交。
3. 系统保留当前会话，注销其他设备的会话。
4. 注销账号：输入密码并二次确认。
5. 系统保留历史内容并标记“已注销面具”，删除通知，释放邮箱。

异常流程：

- 当前密码错误：提示密码错误。
- 新密码强度不足：提示规则。
- 取消注销确认：不做任何变更。

后置条件：

- 改密后可用新密码登录；注销后无法登录，原邮箱可重新注册。

## 6. 数据模型草案

所有时间字段统一保存 UTC，展示时按访问者本地时区转换。列表统一使用 `created_at + id` 游标分页。

### 6.1 用户表 `users`

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `email` | 当前登录邮箱，活动账号唯一；注销时置空以释放邮箱 |
| `deleted_email` | 注销前邮箱快照，仅管理员可见 |
| `password_hash` | Werkzeug PBKDF2 密码哈希 |
| `role` | `user` / `admin` / `super_admin` |
| `status` | `active` / `disabled`（账号注销后写 `deleted_at`，不参与登录） |
| `created_at` | 注册时间 |
| `deleted_at` | 注销时间，未注销为 NULL |

注销账号时将 `email` 置空、把原值复制到 `deleted_email` 并写入 `deleted_at`；历史帖子、回应与图片保留，管理员使用 `deleted_email` 查看历史账号信息；SQLite 唯一约束允许多个 NULL，因此原邮箱可以重新注册。

### 6.2 会话表 `sessions`

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `user_id` | 所属账号 |
| `token_hash` | 会话令牌哈希 |
| `current_mask_id` | 当前面具，登录时为 NULL，选择或切换时写入，销毁当前面具时清空 |
| `expires_at` | 过期时间 |
| `created_at` | 创建时间 |

当前面具必须记录在服务端会话中，不能只依赖前端状态；后端所有写操作都以该字段为准。

### 6.3 面具表 `masks`

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `user_id` | 所属账号 |

## 9. 非功能需求

### NFR-01 可部署性

- 应用可在 PVE LXC 容器中启动。
- 使用 systemd 管理 Flask 服务。
- 应用崩溃后可自动重启。
- 数据库和图片目录位于独立持久化目录。
- 部署地址和端口通过配置指定。
- 不依赖外部邮件、Redis、对象存储或消息队列。

### NFR-02 可迁移性

- 程序、数据库、图片和配置相互分离。
- 提供 `.env.example`。
- 提供数据库备份和恢复说明。
- 不在代码中硬编码校园网 IP。
- 未来可在前面增加域名、HTTPS 或反向代理。

### NFR-03 可用性

- 主要流程出现明确中文反馈。
- 空列表显示空状态。
- 发帖和图片上传显示提交中状态。
- 移动浏览器可以查看主要页面，不出现横向滚动。
- 详情页自然滚动，长回应列表不设固定高度、不出现页面内嵌套滚动条。
- 多图相册单图高度不超过视口高度的 60%，图片不裁剪。

### NFR-04 数据一致性

- 删除帖子时先提交数据库删除，再删除磁盘文件；文件删除失败只记日志，不回滚已提交的删除。
- 删除回应时，帖子回应数同步更新。
- 面具销毁不删除历史帖子和回应。
- 通知删除占位不保留已经删除的正文。
- 当前面具选择必须由服务端会话校验，不能只信任前端提交的面具 ID。

---

### NFR-05 安全与滥用控制

- 密码只保存 Werkzeug PBKDF2 哈希，任何接口与日志都不出现明文密码。
- 会话使用 httpOnly Cookie，禁止前端脚本读取；`COOKIE_SECURE` 由配置控制，接入 HTTPS 后置为 true。
- 所有写操作以服务端会话中的身份与当前面具为准，不信任前端提交的账号 ID 或面具 ID。
- 发帖与回应的 30 秒限速由服务端计时，切换面具不重置。
- 上传文件校验文件头魔数、使用随机文件名、存放于非公开目录，禁止在该目录执行脚本。
- 全站查询使用参数化语句，不拼接用户输入。

## 14. v0.5 确认与默认决策记录

本章是决策留痕。其中 C-01 至 C-14 与 14.2 的默认值已并入正文对应章节，实现时以正文为准，本章用于回溯每条规则的确认时间与选择理由。

### 14.1 本轮新增确认

| 编号 | 决策 | 结果 |
|---|---|---|
| C-01 | UC-01 注册后是否自动领取面具 | 不自动领取；注册后建立登录态，用户进入“我的面具”手动领取并设为当前面具 |
| C-02 | 当前面具保存位置 | `sessions.current_mask_id` 服务端字段；登录为 NULL，选择/切换写入，销毁当前面具时清空 |
| C-03 | 帖子正文长度 | 1–2000 个 Unicode 字符 |
| C-04 | 回应正文长度 | 1–500 个 Unicode 字符 |
| C-05 | 删除文件顺序 | 先提交数据库删除，再删除图片文件；失败记录日志，不回滚已提交删除 |
| C-06 | 历史内容删除权限 | 按账号拥有对应历史面具校验，不要求切回原面具 |
| C-07 | 热门筛选与缓存 | 支持标签；全站及 7 标签共 8 份进程内缓存，每 5 分钟刷新，过期先返旧缓存并后台刷新 |
| C-08 | 搜索 | 单/双字参数化 `LIKE`，三字及以上 FTS5 trigram；标题、正文、回应命中合并为一条 |
| C-09 | 图片处理 | 校正方向、剥离 EXIF、WebP quality 85；静态原图≤5MB，动画≤10MB，缩略图≤1MB |
| C-10 | 详情布局 | 图片在正文上方；详情页自然滚动；多图横向相册，最大高度 `60vh`，不裁剪 |
| C-11 | 账号注销 | 历史内容与图片保留，公开身份统一为“已注销面具”；通知删除；原邮箱可重新注册且与旧账号隔离 |
| C-12 | 举报 | 仅登录用户可举报；可重复举报，每分钟最多 3 次；不自动隐藏；管理员保留或删除并统一结案 |
| C-13 | 管理员层级 | 唯一超级管理员 + 普通管理员；超级管理员可管理普通管理员；普通管理员不能管理管理员 |
| C-14 | 停用管理员邮箱 | 邮箱继续绑定原账号，只允许恢复原账号，不释放给新管理员账号 |

### 14.2 默认决策

以下细节未逐项询问，采用常规实现并作为本版本默认值：

1. 普通 UI 间距、颜色、按钮样式、加载动画和响应式断点由实现阶段统一设计。
2. 使用 Flask + Waitress，由 systemd 管理单实例服务；前端采用 React/Vite/TypeScript，资源本地打包。
3. 最新列表、搜索、通知和后台列表首次加载 20 条，使用 `created_at + id` 游标滚动加载。
4. 时间数据库统一保存 UTC，前端按访问者本地时区显示相对时间和完整时间。
5. 游客导航为“回声洞 / 搜索 / 登录 / 注册”；登录导航为“回声洞 / 搜索 / 写树洞 / 通知 / 个人中心”。
6. 个人中心包含邮箱、当前面具、面具数量、我的面具、我的帖子、账号设置和退出登录；账号设置默认折叠。
7. 修改密码成功后保留当前会话、注销其他会话；退出和注销账号需要确认。
8. 图片说明为可选单行纯文本，最多 100 字符，禁止 URL/裸域名；只作 `alt`，大图预览显示。
9. 相册桌面端使用按钮和键盘切换，移动端使用区域内滑动；不自动轮播，预加载相邻图片。
10. 管理员后台首页统计每 30 秒刷新，按服务器自然日统计“今日新增”。
11. 举报队列按待处理数量降序；数量相同时按目标最新待处理举报时间升序；支持原因和状态筛选。
12. 管理员删除内容不可恢复，必须固定理由 + 至少 10 字说明 + 二次确认；审计日志只读，不导出。
13. 普通管理员只能查看自己的审计日志，超级管理员可查看全部；查看普通面具映射不记录，查看已注销面具映射记录日志。
14. 管理员创建普通管理员时必须使用未注册邮箱，临时密码永久有效，不强制首次修改；超级管理员重置密码需理由和二次确认。
